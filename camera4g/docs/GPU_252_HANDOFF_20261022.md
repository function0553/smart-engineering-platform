### GPU 准备和启动

示例仓库路径 `/opt/hyc`，按实际路径调整。GPU 独立 Python 环境安装 `ppe/requirements-cuda.txt`。打卡原版 facekit/face_engine 已恢复到 attendance/vendor_original，完整 Python 依赖见 attendance/requirements-gpu.txt；SCRFD/ArcFace 权重按 attendance/face-models.json 从受控原部署恢复并校验。GPU 姓名音频适配器还需 espeak-ng 和 ffmpeg。

1. 复制 `deploy/gpu.env.example` 为 `/etc/camera4g/private/gpu.env`，填写真实流地址与凭据。该文件由 Bash 加载，按 shell 语法引用特殊字符，限制为服务用户可读，禁止 `bash -x` 输出凭据。
2. 从 `ppe/config.example.json` 创建私有 `video.json`，设 `device="cuda"`、实际 `device_id`、模型绝对路径、camera_id 和主码流尺寸；确认 MAIN 流后才设 `main_source_verified=true`。GPU 启动脚本拒绝 CPU 配置。
3. 从 `attendance/config.example.json` 创建私有 `attendance.json`，填写模型、活体模型、数据库和 cameras。`gpu_id` 默认 1；单 GPU 改为 0，多 GPU 可让 PPE 使用 0、打卡使用 1。
4. 从 `preview/config.example.json` 创建私有 `preview.json`，让 inference_port 与 PPE bind.port 一致，并恢复 HLS/RTSP 媒体链路。

```sh
cd /opt/hyc
# 启动脚本：GPU 安全帽、反光背心检测
bash camera4g/deploy/start-gpu.sh ppe
# 启动脚本：GPU 人脸打卡
bash camera4g/deploy/start-gpu.sh attendance
# 启动脚本：GPU 现有视频、检测历史代理
bash camera4g/deploy/start-gpu.sh preview
```

三条是独立常驻进程，使用不同终端或 systemd 实例管理。生产配置用户、目录和权限后：

```sh
sudo cp camera4g/deploy/camera4g-gpu@.service.example /etc/systemd/system/camera4g-gpu@.service
sudo systemctl daemon-reload
sudo systemctl enable --now camera4g-gpu@ppe camera4g-gpu@attendance camera4g-gpu@preview
```

PPE/preview 可先进行不连接视频的本地预检：

```sh
bash camera4g/deploy/start-gpu.sh ppe --check-only
bash camera4g/deploy/start-gpu.sh preview --check-only
```

GPU nginx 模板须合并进现有配置，替换占位符后 `nginx -t` 再重载，不覆盖原 nginx 主配置。


## 交给 252 后端的算法接口

### 安全帽、反光背心

基础地址 `https://实际GPU域名:29478`，鉴权 `Authorization: Bearer <PPE_VIDEO_CAMERA_TOKEN>`。

- `GET /v1/cameras/{camera_id}/status`：视频和推理状态。
- `GET /v1/cameras/{camera_id}/results`：四类检测 `hardhat`、`no-hardhat`、`safety vest`、`no-safety vest`。
- persons 为匿名人员与穿戴关联，没有新鲜观测时撤回旧状态；不能作为实名打卡身份。

视频/历史基础地址 `https://实际GPU域名:29480`，HTTP Basic：`viewer:<PPE_PREVIEW_PASS>`。

- `GET /media/hls/raw-main/index.m3u8` 及分片。
- `GET /api/results-history`：短时检测历史。
- `GET /config.public.json`：叠框参数。

坐标、时间与断流规则见 [`PPE_BACKEND_20261009.md`](PPE_BACKEND_20261009.md)，其中历史回环/SSH 地址由本文 HTTPS 地址替代。252 现有代理对外路径仍为 `/api/ppe/cameras/...`、`/ppe-live/...`，GPU token 不下发客户端。

### 人脸打卡（算法 API，由 252 后端集成）

基础地址 `https://实际GPU域名:29482`，全部使用 `Authorization: Bearer <ATTENDANCE_ADMIN_TOKEN>`。该 token 有人员录入、读取、测试清除权限，252 必须按业务角色限制调用。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/status` | 模型、摄像头、活体和运行状态 |
| GET | `/api/dashboard` | 状态、人员、近期打卡 |
| GET | `/api/people` | 人员列表 |
| GET | `/api/attendance` | 打卡记录 |
| POST | `/api/enroll` | 录入照片、姓名和播报音频 |
| POST | `/api/voice/confirm` | 人工听音后确认，参数 attendance_id |
| POST | `/api/attendance/clear` | 仅测试，参数固定 `{"scope":"today","test_only":true}`，清除前归档 |

录入请求：

```json
{
  "person_id": "EMP001",
  "name": "测试人员",
  "photo_base64": "<清晰单人正脸图片base64，图片不超过5MB>",
  "voice_text": "测试人员打卡成功",
  "voice_pcma_base64": "<8kHz单声道G.711 A-law原始音频base64>"
}
```

上面的 voice_text/voice_pcma_base64 为兼容旧调用的可选字段。新版可仅提交编号、姓名和照片，由 GPU 配置的本地命令准备姓名音频；252 提供对应录入入口。`attendance/local_preview.py` 为历史 Windows 工具。广播链路和现场听音仍需验证，submitted_unverified 不等于确认听到。

规则保持北京时间 08:00 起记录、09:05:00（含）前正常、之后迟到、每人每天首条打卡。GPU 保存推理所需特征和识别记录，252 使用独立镜像表按 sourceId/attendance_id 幂等入库，不能把 PPE track_id 当人脸人员编号。
