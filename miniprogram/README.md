# 智慧工程施工日报与施工影像资料 · 微信小程序开发工程

工程版本0.3.0，使用微信原生页面，无 npm 构建依赖；提供平台账号登录、日期与自动天气、日报填报与汇报记录，以及施工影像资料册、可恢复的原图上传队列和汇总 Word 历史版本。与网页、安卓 APP 共用后台及用户提供的两个 Word 模板，需后台0.5.0或更新版本。

## 导入与本机联调

1. 将本工程解压到目录，例如 `D:/codex/daily-report-miniprogram`。
2. 微信开发者工具选择“导入项目”，选择含 `project.config.json` 的目录。当前 AppID 为 `touristappid`，用于无正式 AppID 的游客工程；按工具界面选择测试号/游客模式，不开启云开发。有正式 AppID 后替换此值。
3. 启动既有智慧工程后台。电脑访问 `http://127.0.0.1:5186/#daily-report` 应能打开；本机默认后台也为此地址。
4. 微信开发者工具的本地开发设置中，按开发工具要求启用本机 HTTP 联调的“不校验合法域名”选项。工程默认 `urlCheck: true`，没有关闭正式域名检查。真机与发布时使用已配置合法域名的 HTTPS 后台。
5. 登录页填写后台地址及现有平台账号/密码。用户名不是手机号或微信账号；游客 AppID 不创建或替代平台账号。后台尚未初始化时，先在电脑网页建立管理员。
6. 依次填写“日报信息 → 施工片区 → 计划与照片”，点“提交并生成 Word”。提交成功后，文字、原图和生成的 Word 统一保存在服务器，再下载到手机供预览或转发。
7. “我的汇报记录”查看当前账号的提交；管理员显示“全部汇报记录”，可筛选工程、日期、填报人及编号，查看文字与原图，并下载已保存的 Word、原图与填写数据 JSON。
8. 日报页的“施工影像资料”进入资料册模块。切换前会保存既有日报草稿；返回后仍可继续日报填写。

后台地址不带路径。`127.0.0.1` 在真机代表手机本身，工程默认值用于电脑开发联调。252已部署后台，地址为 `https://211.139.12.141:21901`，使用项目内部CA；安卓APP内置信任该证书。微信不能使用安卓的证书信任配置，微信真机和正式发布仍需受信HTTPS域名、AppID及合法域名配置。本工程保留游客AppID，供导入开发者工具使用。

## 填写规则

- 默认工程与四个片区来自用户提供的管网改造三期模板；当天施工数量、人员、机械与计划保持空白。管网完成比例、水表完成数量按各自口径填写。
- 作业人员填写整数人数；交通安保人员可填写人数或实际情况。未核实的非必填项可留空，不自动转成“无”。未施工的片区填写停工说明。
- 天气默认取经开区参考点，可调整项目坐标。天气跟随施工日期，接口不可用时不会填晴，可手动输入现场情况。手动输入后关闭自动模式。自动天气属于预报/历史模型资料，界面与生成文档保留来源标注。
- 每个符合数据要求的模板导出按当前填写生成。当前草稿按账号和后台隔离，原图写入本小程序私有文件空间，文字与说明写入本机草稿索引；重开时恢复原图、说明及填写内容。修改说明不重写原图，移除照片后不会在下一次重开时恢复。
- 本机草稿以“填写内容与照片草稿已保存在本机”提示为准。保存失败不删除上一份已保存草稿；每个账号和后台在本机保留一份当前草稿。草稿未提交时仅在本机，跨设备继续编辑需导入此前导出的 JSON；已提交的记录可从服务器重新下载 JSON，包含原图。
- 照片为 PNG/JPEG，单张≤5MB，合计≤20MB，最多12张，保持原图字节；微信拍照可能产生较大的照片，请控制尺寸或选择较小原图。照片说明与选择顺序一起写入 Word。
- “导出填写数据”保存包括本次照片的 JSON；可从微信聊天文件导入此前导出的 JSON。需要微信 `shareFileMessage` 功能支持，版本不支持时只能保存在小程序文件空间。
- “日报已提交到服务器”表示服务器已将文字、原图、Word一次性写入数据库。随后下载失败不撤销提交，可在汇报记录中重新下载。相同内容的网络重试复用提交标识；修改后再次提交会生成另一条记录，保留原版本。没有后台自动上传未提交草稿。
- 252文字及Word保存在 `/opt/smart-engineering/shared/workspace.sqlite` 的 `daily_reports` 表，原图字节保存在 `daily_report_photos` 表。管理员查询全部提交；其他账号只能查询自己的记录，照片和下载接口同样检查权限。

## 施工影像资料册

此模块按用户提供的 `开挖~回填-汇总版影像资料(甲秀南路).docx` 生成。新建资料册后填写工程、道路及桩号；无桩号的探坑等施工可填写“施工内容”。每册支持1～32个路段，每路段支持1～16道工序，工序名称和完成日期可修改。默认八项为路面拆除、沟槽开挖、沟槽验收、垫层施工、管道安装、沟槽中粗砂回填、压实度检测、路面混凝土恢复。

1. 在相应工序“拍照 / 选择原图”，可批量选择 PNG/JPEG 原图。单张≤5MB，每工序≤6张，每册≤120张、总计≤24MB。选择时明确使用原图，保留真实字节和尺寸；照片说明在上传前填写，当前接口不修改已上传原图说明。
2. 原图先复制到本小程序私有文件空间，再写入按后台、账号和资料册隔离的队列索引，逐张保存到服务器。部分失败、网络回复丢失或重开页面时保留待上传队列，点击“重试上传原图”复用照片编号；服务器重复识别不会再保存同一工序的同图。只有服务器确认保存或用户明确移除时，才删除本模块对应的原图草稿。关闭页面只清理本页下载的预览缓存，不清理待上传原图。
3. “保存填写”将资料册文字同步到服务器。本机未保存填写可在重新打开资料册时恢复；新建页的未保存草稿可从列表继续。其他设备修改导致版次冲突时，本机草稿保留，用户明确“重新加载”后才用服务器内容替换；待上传原图仍保留。
4. “生成汇总 Word”按原模板生成独立版本。生成请求编号在服务器确认前持久保留，响应丢失后继续生成会复用同一编号。下载、手机存储或文档预览失败不会移除服务器版本，可在“历史 Word 版本”重新下载、查看或转发。文件名包含完整版本编号，避免同一分钟生成的多个文档互相覆盖。
5. 操作员只能查看自己的资料册；管理员可查看所有人的填写和原图并下载 Word；只读账号隐藏新建、上传、编辑、生成操作。照片、Word及其他读写接口由后台再次校验权限。

资料册文字、原图和不可变 Word 版本在252的 `/opt/smart-engineering/shared/workspace.sqlite` 中分别保存到 `photo_archives`、`photo_archive_images`、`photo_archive_exports`、`photo_archive_export_images`。小程序、网页和安卓 APP 使用同一组资料册接口及账号数据，不另建数据库。新建但尚未保存的文字、尚未确认上传的原图仅在当前设备的本机草稿中。

## 接口与发布前置

接口以 `/api/mobile` 开头：`/login`、`/me`、`/logout`、`/daily-report/template`、`/daily-report/weather`；`/daily-report/submissions` 提交及列表；`/daily-report/submissions/:id` 详情，后接 `/word`、`/data`、`/photos/:index` 下载。会话为12小时有效的移动端 Bearer，后台保存其摘要；只读账号不能提交日报。旧 `/daily-report/export` 保留用于旧客户端兼容，但该接口不保存服务器汇报记录；多人汇报应使用0.2.0客户端。

施工影像资料接口同样以 `/api/mobile` 开头：`GET /photo-archives/template`，`GET/POST /photo-archives`，`GET/PUT /photo-archives/:id`，`POST /photo-archives/:id/photos`，`GET/DELETE /photo-archives/:id/photos/:photoId`，`POST /photo-archives/:id/exports`，`GET /photo-archives/:id/exports/:exportId/word`。

当前基础库配置 `3.17.0`；若本机开发者工具未安装该版本，应按工具提供的版本选择兼容基础库。API 使用 `chooseMedia`、文件系统、`openDocument` 与能力检测后的 `shareFileMessage`。

交付的0.3.0导入包包含本目录的原生源码、游客 AppID 和开发配置，不含账号、密码、业务图片或数据库。可直接导入开发者工具，不需要 npm install。正式小程序发布仍需用户的 AppID、微信可接受的受信 HTTPS 后台及合法域名配置。当前默认后台保持本机开发值；登录页可设置实际后台。

本工程尚未在当前微信开发者工具和微信真机验收。逻辑测试中的微信 API、文件系统和选择照片是模拟调用，即使配合真实隔离后台及 Word 内容验证，也不能代替微信原生相机、文档预览、转发或实际网络环境验证。官方模拟组件工具使用的原生编译器为其依赖内置版本，组件截图和编译结果同样不能等同于当前开发者工具或微信真机通过。

天气服务采用 [Open-Meteo](https://open-meteo.com/en/docs)，免费接口用于开发评估；商业生产使用需配置商业天气服务，目前支持后台环境变量 `WEATHER_API_KEY`，客户端不持有该密钥。参见 [服务使用范围](https://open-meteo.com/en/pricing)。
